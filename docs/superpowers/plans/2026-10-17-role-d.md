# Role D implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task.

**Goal:** Implement the D deliverables as a persistent module ready for B's backend, with a local REST/WebSocket harness.

**Architecture:** Framework-independent TypeScript domain service, injected clock and event sink, SQLite snapshot adapter. The existing frontend mock stays intact. B can use its own persistence adapter and forward events through its existing bus.

**Tech Stack:** Node 24, TypeScript, node:sqlite, node:test, ws (harness only).

**Spec:** `.plans/role-d-memory-anomaly-data-spec.md`, `.plans/shared-contracts.md`; rule formulas from `产品方案.md`.

## Global constraints

- No frontend changes; C owns payment, transaction checks and sharing filters.
- Contract names and flattened WebSocket payloads stay unchanged.
- Demo cold start enables only rules 1, 4, 7, 8.
- Defaults: UTC (contract examples), 60 seconds response window, 15 minute snooze, 3 day refill lead. These are configurable and must be documented.
- Catalog is explicitly synthetic demo data, not evidence of certification or medical advice.

## Review focus

- Rewind/restart must not repeat reminders or inventory movements.
- Duplicate receipts, timeout/late-answer races and low stock must not double-debit or inflate inventory.
- Multiple orders/reminders must not consume answers intended for a different prompt.
- Pausing, changing or deleting a memory invalidates outstanding prompts and snoozes.
- Invalid HTTP/WS inputs and filesystem paths must not mutate state or expose local files.
